# Private input relay

Server-hosted browser input now opens one authenticated loopback WebSocket to the browser host worker. The public BB control socket and viewer UI remain unchanged. Subsequent input batches bypass host RPC serialization/routing. The connection is established when the viewer's control socket opens. Other hosts, older workers and failed private handshakes retain the existing RPC path. A command sent on an established private connection is never replayed through fallback after an error.

Each listener binds 127.0.0.1, requires a random single-use 256-bit token, accepts one controller, expires after three seconds if unused, and belongs to one session/client. There is a 16-listener cap per session. Input schema and bounded queues apply at both public and private boundaries. Each batch runs through the same current session/expiry, private-login and agent-action checks as RPC input. Commands stay ordered; closing either side releases held controls. Session shutdown closes its private listeners. No CDP endpoint or private token is sent to the user-facing client.

Network tests cover authentication, single-controller access, ordering, changing locks, disconnect cleanup, invalid commands and no replay after failure. Server integration checks one controlStart RPC and zero direct RPCs for subsequent private batches; existing RPC fallback and public input validation tests remain.

Measurement: `npx tsx tests/control-latency.mts SESSION_ID` sends 100 heartbeat/no-op batches through the installed public control route. No pointer/key/page mutation occurs. After connection setup, the old RPC route measured median 14.63 ms, p95 29.02 ms, maximum 127.12 ms. Raw control-before.json. This isolates ACK/transport overhead on loopback; it excludes CDP page work, video delivery and real WAN latency. It cannot establish end-to-end scrolling smoothness. The baseline was repeated after checks finished to avoid the first trial's concurrent-check load.

Installed verification after build/reload: public /control responses report transport `direct`. The same 100-heartbeat loopback check measured median 5.52 ms, p95 13.90 ms, maximum 39.53 ms (control-after.json). No concurrent test suite was running during either retained measurement. Shared host load can still vary between runs. The change reduces this measured control-route overhead; no end-to-end FPS, picture-latency or CPU/memory improvement is claimed. The existing thread tab was restored to the same browser profile and URL. All five repo plugins remained running from their permanent paths. Typecheck and the 162-test full suite passed; the subsequently added invalid-command test passed with the three-test relay file.
